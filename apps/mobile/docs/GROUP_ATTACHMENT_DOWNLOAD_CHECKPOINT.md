# Native attachment download — 2026-10-04

## Behavior

Existing file events show the attachment name and a download action. Stale group
projections do not offer download. Live downloads capture bearer/device credentials
of the session that opened the group; group identity and current session/bootstrap
are checked before download and again before export. Changing account prevents
export of a download completed for the old account.

Only canonical relative group/message attachment endpoints are accepted. Redirects
are disabled so bearer/device headers are not followed to an external server. The
stream is bounded to 20 MiB even without Content-Length. Non-200, oversized,
truncated, cancelled and network-failed responses are never offered for saving.

The activity shows progress (indeterminate without known length), cancellation,
saved/cancelled feedback and an explicit retry after failure. Leaving an activity
cancels its network download. No attachment data is written to the app cache.

Android uses ACTION_CREATE_DOCUMENT to let the user select a destination; the
completed bytes are copied on a worker thread. This uses the selected document URI
and needs no broad external-storage permission. There is no automatic file opening.
An explicitly exported file remains in the user's chosen location after logout.

## Scope

This is retrieval of existing web-uploaded group files only. Native new upload,
voice playback, thumbnail preview, attachment pagination and iOS document export
are not implemented by this change. FCM configuration and device gates remain open.
