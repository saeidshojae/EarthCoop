# 📋 خلاصه ویژگی ارجاع پروژه‌ها برای بررسی

## ✅ کار انجام شده

سامانه ارجاع پروژه‌ها برای کمیته‌های تخصص و بررسی‌کنندگان متخصص کاملاً ساخته و فعال شده است.

---

## 📝 ویژگی‌ها

### 1️⃣ **ارجاع پروژه‌ها**
- ✨ ادمین می‌تواند پروژه‌های در حال بررسی را به کاربران فردی یا گروه‌های تخصص ارجاع دهد
- ✨ انتخاب دینامیکی لیست مقاصد (User/Group)
- ✨ افزودن توضیحات برای ارجاع (چرا، برای چه، توقعات)

### 2️⃣ **اطلاع‌رسانی**
- 📧 ارسال ایمیل با جزئیات پروژه
- 🔔 نوتیفیکیشن در سیستم
- 👥 اگر گروه انتخاب شود: تمام اعضای گروه اطلاع دریافت می‌کنند

### 3️⃣ **نمایش وضعیت**
- 🔍 نمایش فوری: کی، کجا، کیست ارجاع شده
- 📊 وضعیت ارجاع: در انتظار / تحت بررسی / تکمیل شده / رد شده
- 💬 نظر بررسی‌کننده (پس از تکمیل بررسی)

### 4️⃣ **تاریخچه کامل**
- 📚 تمام ارجاعات در سیستم ثبت می‌شود
- 🔐 توضیحات محفوظ می‌ماند
- ⏰ تاریخ‌ها و زمان‌ها ثبت می‌شود

---

## 🛠️ چگونه استفاده کنید

### از نقطه نظر ادمین:

```
1. وارد صفحه جزئیات پروژه شوید
2. دکمه "ارجاع برای بررسی" را کلیک کنید (دکمه بنفش)
3. فرم ارجاع باز شده:
   
   ┌─────────────────────────────────┐
   │ ارجاع پروژه برای بررسی         │
   │                                 │
   │ نوع مقصد:    [User ▼ ]         │
   │ اختر مقصد:    [احمد علی ▼]      │
   │ توضیحات:     [متن اختیاری]     │
   │                                 │
   │ [ارجاع]  [لغو]                 │
   └─────────────────────────────────┘

4. نوع مقصد انتخاب کنید (User یا Group)
5. فهرست مقاصد خودکار بارگذاری می‌شود
6. مقصد را انتخاب کنید
7. توضیحات بنویسید (اختیاری)
8. روی "ارجاع" کلیک کنید ✓
```

## 📊 نمایش وضعیت ارجاع

پس از ارجاع، یک جعبه آبی رنگ در صفحه ظاهر می‌شود:

```
┌──────────────────────────────────────┐
│ 📌 وضعیت ارجاع                      │
│                                      │
│ ارجاع شده به:   احمد علی (کاربر)   │
│ تاریخ ارجاع:    2 ساعت پیش          │
│ وضعیت:         در انتظار 🟡         │
│                                      │
│ توضیحات ارجاع:                      │
│ نیاز به بررسی فنی دقیق می‌باشد      │
└──────────────────────────────────────┘
```

## 🔄 جریان کامل

```
پروژه: Pending/Under Review
    ↓
ادمین میل‌دهد "ارجاع برای بررسی"
    ↓
انتخاب مقصد (User یا Group)
    ↓
ثبت توضیحات
    ↓
✓ ارجاع
    ↓
• پروژه "ارجاع شده" علامت‌گذاری می‌شود
• ایمیل به مقصد (یا تمام اعضای گروه)
• نوتیفیکیشن سیستمی
• ثبت در تاریخچه
    ↓
مقصد بررسی‌کننده اطلاع پذیر می‌شود
    ↓
بررسی انجام می‌دهد و نتیجه را ثبت می‌کند
    ↓
وضعیت "تکمیل شده" ⚫ یا "رد شده" ❌
```

- قابل ردگیری و auditable

## 💡 نمونه‌های استفاده

### ارجاع به کاربر تخصص‌دار
```
نوع مقصد: کاربر
مقصد: احمد علی (متخصص فنی)
توضیحات: "لطفاً از لحاظ فناوری ارزیابی کنید"

↓ ارجاع
↓ احمد علی ایمیل دریافت می‌کند
↓ نوتیفیکیشن سیستمی
```

### ارجاع به کمیته
```
نوع مقصد: گروه
مقصد: کمیته نظارت مالی
توضیحات: "نیاز به بررسی تفضیلی بودجه و مالی است"

↓ ارجاع
↓ تمام اعضای کمیته ایمیل دریافت می‌کنند
↓ نوتیفیکیشن برای همه
```

## ⚙️ متطلبات فنی

برای عملکرد درست سامانه:

- ✅ **Database:** مهاجرت اجرا شده (Migration)
- ✅ **Email:** تنظیمات ایمیل فعال (برای نوتیفیکیشن)
- ✅ **Queue:** تنظیمات صف (برای اطلاع‌رسانی بک‌گراند)
- ✅ **User Model:** دارای is_admin یا is_specialist
- ✅ **Group Model:** دارای رابطه users()
