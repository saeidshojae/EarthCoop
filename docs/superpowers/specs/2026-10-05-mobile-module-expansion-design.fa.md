# طرح اتصال ماژول‌های EarthCoop به اپ موبایل

تاریخ: ۲۰۲۶-۱۰-۰۵. وضعیت: بررسی کد و طرح پیشنهادی تکمیل شده؛ پیاده‌سازی این مرحله هنوز آغاز نشده است.

## هدف و وضعیت مبنا

درخواست کاربر، گسترش اپ به بخش‌های موجود سایت است؛ نبود گوشی نباید بررسی و توسعهٔ قابل آزمون را متوقف کند. مبنا نسخهٔ Android Release UAT +15 با رسید d1d40d279766b20afd24e547c0294a725d8281ee است. اپ فعلی شامل ورود، گروه‌ها، فعالیت و پیام متنی، دانلود پیوست موجود، اعلان و خروج است. این پوشش معادل کامل سایت نیست. تست واقعی دستگاه، فعال‌سازی کنترل‌شدهٔ ارسال اعلان و انتشار عمومی همچنان باز هستند. استقلال از گوگل و تاب‌آوری قطع اینترنت طبق دستور کاربر به پایان توسعه موکول است.

## شواهد بررسی

منابع: routes/api-v1.php، routes/web.php، کنترلرها و Resourceهای API/V1 نجم بهار و نجم هدا، NajmBaharAccountQueryService، NajmBaharLedgerQueryService، app/Helpers/BaharMoney.php، تست‌های tests/Feature/Api/V1 و router/runtime/features اپ. بررسی روی محتوای checkout ادغام‌شده انجام شده است؛ نسخهٔ +15 تغییر ماژولی در این فایل‌ها ندارد. فایل ضمیمهٔ آرمانی مبنای این ممیزی نیست.

وجود API و تست قراردادی اثبات اجرای موفق درخواست در هاست با حساب واقعی نیست. در این مرحله تست تازه‌ای اجرا نشده است؛ رسید تست‌های +15 مربوط به قابلیت‌های پیشین است.

نجم بهار نام ماژول مالی در مخزن است؛ نجم هدا ماژول گفت‌وگو و اقدامات هوشمند است. این دو اتصال مستقل دارند. ترتیب جدول پیشنهاد است و به معنای آماده بودن هم‌زمان همهٔ بخش‌ها نیست.

## انتخاب فنی

اتصال بومی به API v1 موجود توصیه می‌شود: از قرارداد، کنترل اختیار و Session فعلی استفاده می‌کند و وابسته به کوکی صفحات وب نیست. باز کردن صفحات سایت سریع‌تر است اما پوشش بومی و چرخهٔ ورود یکپارچه ایجاد نمی‌کند. بازسازی هم‌زمان همهٔ ماژول‌ها دامنه و خطر بازگشت را افزایش می‌دهد. انتخاب پیشنهادی، یک جریان قابل تحویل در هر مرحله است.

## اولین جریان: کیف پول و تاریخچهٔ نجم بهار

ورودی «نجم بهار» به Home اضافه می‌شود. صفحهٔ محافظت‌شدهٔ /najm-bahar حساب متعلق به کاربر جاری را با GET /najm-bahar/account نمایش می‌دهد: شماره حساب، نام، وضعیت، موجودی حساب اصلی و موجودی تجمیعی با برچسب متمایز. داده‌های مالی فقط از پاسخ سرور خوانده می‌شوند.

فیلدهای active_gol، dim_available_gol، dim_committed_gol، dim_total_gol و total_gol جداگانه نمایش داده می‌شوند؛ مبلغ متعهد با مبلغ قابل استفاده یکسان تلقی نمی‌شود. واحد ذخیره و API عدد صحیح گل است؛ طبق BaharMoney، هر بهار ۱۰۰ گل است. قالب نمایش با تقسیم و باقی‌ماندهٔ صحیح ساخته می‌شود، بدون محاسبهٔ اعشاری شناور یا تبدیل به پول رسمی.

تاریخچه با GET /najm-bahar/transactions و limit=20 بارگذاری می‌شود؛ cursor از meta.pagination.next_cursor و has_more خوانده می‌شود. نمایش مطابق پاسخ سرور جدیدترین مورد در ابتداست. صفحهٔ نخست فیلتر حساب اعمال نمی‌کند تا دامنهٔ حساب‌های متعلق به کاربر، مطابق API، حفظ شود. ردیف شامل مبلغ، جهت، نوع، وضعیت، طرف مقابل در صورت وجود، شرح و تاریخ است. شناسهٔ تکراری هنگام افزودن صفحهٔ بعد حذف می‌شود؛ پاسخ صفحهٔ بعد پس از refresh یا تغییر حساب به فهرست جدید اضافه نمی‌شود.

کنترلر حساب و تاریخچه وضعیت مستقل دارد: شکست تاریخچه نباید حساب موفق را مخفی کند و شکست حساب نباید به‌اشتباه موجودی صفر نشان دهد. بارگذاری، نبود حساب، تاریخچهٔ خالی، پاسخ نامعتبر، انقضای نشست و خطای قابل تلاش دوباره حالات متمایز هستند. 404 حساب پیام «حساب نجم بهار یافت نشد» می‌دهد؛ هیچ حسابی هنگام خواندن ساخته نمی‌شود. نبود حساب مانع نمایش تاریخچه‌ای که API مستقلاً مجاز می‌داند نیست.

در این جریان عملیات مالی، ایجاد حساب و کش پایدار مالی اضافه نمی‌شود. داده فقط در حافظهٔ نشست فعلی است و هنگام خروج/تغییر حساب کنار گذاشته می‌شود. بنابراین موجودی قبلی در خطای refresh به‌عنوان موجودی تازه نمایش داده نمی‌شود؛ تاریخ آخرین دریافت و خطا روشن می‌ماند. این انتخاب مرحلهٔ نمایش است؛ انتقال و پرداخت جزو مرحلهٔ بعد هستند.

## مرزهای نشست و مسیریابی

Repository از ApiClient مشترک و نشست captureشدهٔ همان صفحه استفاده می‌کند. پیش و پس از هر انتظار شبکه، هویت کاربر، token، device و epoch نشست بررسی می‌شود. پاسخ دیررس حساب قبلی و عملیات کنترلر disposeشده نباید صفحه را به‌روز کنند. ورود مستقیم به مسیر نیز نیازمند نشست معتبر و bootstrap مجاز است. ورود Home هنگام شروع خروج غیرفعال می‌شود.

لینک معنایی نجم بهار در این جریان فعال نمی‌شود؛ فقط لینک‌های واقعاً پیاده‌سازی‌شده اجازهٔ مسیریابی دارند. استفاده از URL دلخواه پاسخ یا WebView احراز هویت جایگزین API نیست.

ساختار پیشنهادی: features/najm_bahar برای DTO، repository، controller و صفحه؛ تزریق repository با guard نشست در production_runtime؛ builder مسیر در app_router؛ callback ورودی در home_screen. سرور، schema، کلید امضا و وابستگی‌ها در این جریان تغییر نمی‌کنند.

## پذیرش بدون گوشی

تست DTO با نمونهٔ واقعی ساختار Resource و اعداد بزرگ قراردادی؛ قالب صحیح ۱۰۰ گل و باقی‌مانده؛ پاسخ نامعتبر بدون نمایش صفر ساختگی؛ 404 بدون POST؛ headers احراز هویت/device؛ cursor از meta و حذف تکرار؛ خطای صفحهٔ بعد بدون پاک کردن تاریخچهٔ قبلی؛ refresh هم‌زمان و پاسخ دیررس؛ خروج و تعویض حساب پیش/حین پاسخ؛ عدم ارسال درخواست برای نشست مسدود؛ ورود Home و guard مسیر؛ Widget حالات بارگذاری، موفق، خالی و retry. سپس formatter، analyzer و کل تست‌های موبایل در CI اجرا می‌شوند. فقط بعد از موفقیت و بررسی تغییر، APK جدید ساخته می‌شود؛ build ناقص به‌عنوان قابلیت آماده گزارش نمی‌شود.

تست دستگاه بعداً شامل باز شدن صفحه، مقایسهٔ مبلغ و تاریخچه با همان حساب سایت، حساب فاقد کیف پول و تعویض حساب است. تست‌های قبلی اعلان/پیام/پیوست محفوظ هستند.

## نکات لازم برای جریان‌های بعد

انتقال و پرداخت باید پیش‌نمایش و تأیید کاربر، مبلغ صحیح گل، منبع مجاز، Idempotency-Key پایدار برای یک قصد و بازیابی نتیجهٔ مبهم داشته باشند؛ POST مالی به صف عمومی آفلاین وصل نمی‌شود. UI نباید موجودی یا اختیار سرور را محلی حدس بزند.

در NajmHodaConversationController::message پیام کاربر قبل از executeChat ذخیره می‌شود و POST مسیر گفت‌وگو middleware idempotency ندارد. شکست 502 ممکن است همراه با ذخیرهٔ پیام باشد. ارسال مجدد یا اضافه کردن کلید به هدر به‌تنهایی تضمین جلوگیری از تکرار نیست. پیش از پیاده‌سازی retry گفت‌وگو، باید جریان بازیابی و قرارداد سرور بررسی شود. پاسخ مدل دستور اجرای خودکار عملیات نیست؛ پیشنهاد، رضایت و اجرا مسیرهای جداگانه و تحت اختیار سرور هستند. تست NajmHodaMobileJourneyTest اجرای مدل را mock می‌کند؛ کیفیت/دسترسی سرویس واقعی از آن نتیجه نمی‌شود.

## بازبینی طرح

دامنهٔ اولین تحویل محدود و قابل آزمون است؛ ورودی و خروجی از API موجود مشخص‌اند؛ موجودی اصلی و تجمیعی، گل و بهار، نبود حساب و صفر، و API موجود و پوشش Flutter از هم تفکیک شده‌اند. مراحل بعد نیازمند طرح جریان خودشان هستند. این سند ادعای پیاده‌سازی، تست تازه، انتشار هاست یا اتمام اپ ندارد.
