# متمم طراحی Group Control Center — حفظ جست‌وجوی تب‌ها

**تاریخ:** 2026-08-27  
**Branch:** `agent/pre-main-ui-polish`  
**Parent spec:** `docs/superpowers/specs/2026-08-27-group-experience-control-center-design.md`

## تصمیم تکمیلی قطعی

قابلیت جست‌وجوی موجود در پنل فعلی گروه، بخشی از capabilityهای قابل‌حفظ است و در بازطراحی نباید حذف، تضعیف یا به جست‌وجوی کلی مبهم تبدیل شود.

## الزامات

1. هر تب جدید Control Center که در implementation فعلی پنل قابلیت جست‌وجوی موضوع/محتوا دارد، باید همان قابلیت را در محل جدید حفظ کند.
2. جست‌وجو باید contextual و محدود به همان تب باشد؛ تغییر query یک تب نباید نتایج تب دیگر را تغییر دهد.
3. حداقل تب‌های فهرستی «محتوا» و «اعضا» باید search field واضح و قابل‌دسترسی داشته باشند؛ در «حکمرانی» نیز هر فهرست قابل‌جست‌وجوی فعلی (مانند انتخابات/گزارش‌ها در صورت وجود) باید search contract فعلی را حفظ کند.
4. اگر تب فعلی «گروه‌ها»/جست‌وجوی گروه‌های مرتبط در Control Center جدید حذف یا جابه‌جا شود، قابلیت جست‌وجوی آن نباید بی‌مقصد حذف شود؛ محل نهایی آن باید در Capability Inventory ثبت شود.
5. جست‌وجو باید حداقل همان فیلدهای فعلی را پوشش دهد؛ برای نمونه در اعضا نام/نقش/ایمیل، و در گروه‌ها نام/محتوا طبق implementation موجود.
6. حالت empty-state برای «نتیجه‌ای یافت نشد» باید واضح باشد و پاک‌کردن query باید فهرست کامل همان تب را بدون reload صفحه برگرداند.
7. جست‌وجو باید client-side بماند مگر اینکه implementation فعلی یا حجم داده ضرورت backend search را اثبات کند؛ این مرحله مجوز توسعه backend عمیق نیست.
8. regression tests باید وجود inputهای جست‌وجوی هر تب، scope صحیح filtering و حفظ search capabilityهای فعلی را کنترل کنند.

## معیار پذیرش

بازطراحی فقط وقتی قابل قبول است که inventory نهایی نشان دهد هر search capability فعلی یکی از این وضعیت‌ها را دارد: «حفظ‌شده در همان تب»، «منتقل‌شده به تب/نمای مشخص»، یا «عمداً حذف‌شده با تأیید جداگانه». در این مرحله حالت سوم مجاز نیست.
